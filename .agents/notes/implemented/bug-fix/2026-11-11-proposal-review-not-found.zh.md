# Agent Note: 缺失和不可见提案的审核响应

Status: implemented

[English](2026-11-11-proposal-review-not-found.md) | 中文

## 问题

提案审核在已认证工作区内查询目标提案。提案缺失或不可见时，服务在任何写入前抛出 `proposal was not found`，但 HTTP 适配器把这项领域拒绝归为内部故障。

## 决策

[创作 HTTP 控制器](../../../../packages/api/novel-authoring-http/src/index.ts) 仅在 `Error` 的消息精确等于 `proposal was not found` 时返回 `404 {"error":"not_found"}`。缺失和跨工作区的标识符得到相同响应。审核服务保留工作区限定查询和先查询后写入的顺序。权限错误映射为 403，意外故障映射为隐藏详情的 500 响应。

## 考虑过的替代方案

**匹配所有包含“not found”的消息。** 基础设施故障和其他领域错误也可能包含这些词。精确匹配可以处理已有的审核拒绝，而不改变其他错误的分类。

## 后果

客户端可以把不可用提案视为查询失败，而不会得知它是否存在于其他工作区。适配器依赖一条已有领域错误消息；未来修改该消息时，必须同时更新映射与回归。

## 测试

[控制器测试](../../../../packages/api/novel-authoring-http/tests/controller.spec.ts) 将真实审核服务与数据库空结果组合，验证相同的 404 响应和零写入，并确认即使正文包含外部工作区，传入服务的仍是已认证工作区。相似错误消息、意外异常和抛出的字符串仍返回 500；权限错误仍返回 403。
