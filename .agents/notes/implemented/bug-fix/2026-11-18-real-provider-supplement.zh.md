# Agent Note: 限制追加真实供应商验收的次数

Status: implemented

[English](2026-11-18-real-provider-supplement.md) | 中文

## 问题

原验收额度已经耗尽，无法验证新生成的真实初稿及其续写。重置账本会混淆历史失败和新授权任务；脚本重启后也无法判断结果不明的提交是否已计费。基于固定模型数据完成续写，不能证明真实初稿可以在重启后被召回。

## 决策

[本地验收脚本](../../../../deploy/local-test/README.zh.md#supplemental-real-acceptance)将唯一一份两次任务的补充账本绑定到已耗尽的历史账本，并将[原固定准备续跑](2026-11-13-bounded-real-provider-resume.zh.md)保留为独立操作。两份账本共用 worker 管理锁。追加流程要求当前应用镜像具有完整的固定模型验收证据，并通过指定模型的凭据检查。每次 HTTPS 提交前原子写入预留次数和请求键。

第一次真实任务创建独立草稿数据。账本记录初稿任务、已核验快照的摘要、模型和续写指令摘要。跨进程恢复要求此检查点存在、只预留过一次、并以同一个测试空间所有者重新登录。一次性测试凭据独立保存在本地，由 Windows DPAPI 保护，不进入报告或容器挂载。证据缺失或不一致时禁止提交，不重发结果不明的请求。

第二次预留前，worker 用受限身份和完全相同的续写指令及条数限制执行检索。所有来源必须属于第一次任务。脚本比对第二次任务落库的上下文和检索预选结果，并在重启后比较完整快照。无论业务验收结果如何，都单独核验固定模型 worker 的恢复结果。

## 考虑过的替代方案

**重置历史计数或直接增大上限。** 这会混合独立尝试，并可能在证据缺失的情况下误重放。唯一的独立账本同时保留归因和追加上限。

**仅用一次真实任务续写固定模型数据。** 这能验证检索修复配合真实续写，但不能证明新的真实历史在重启后可以被读取。

**用相同的键重发任意请求以恢复任务。** 请求键无法证明中断任务是否已被供应商接受、计费或完成。恢复只从已核验的初稿开始，且只能发生在续写预留之前。

## 影响

初稿检查点写入前中断可能导致一次预留无法继续使用；第二次预留后中断，即使没有结果也会耗尽剩余额度。遗留锁需要操作者检查。脚本限制自身提交次数，不能给出金额上限。供应商结果、上下文一致性和重启后的实际持久化需要部署证据；模拟调用仅验证程序行为。
