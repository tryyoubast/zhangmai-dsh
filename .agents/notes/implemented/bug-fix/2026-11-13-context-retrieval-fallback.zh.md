# Agent Note：严格优先的上下文检索与无密钥续写检查

Status: implemented

[English](2026-11-13-context-retrieval-fallback.md) | 中文

## Problem

`plainto_tsquery` 用 AND 连接规范化词项。完整创作指令包含历史故事记录没有的输出格式词。真实验收保存了三条草稿，却没有选择历史上下文；短关键词模拟没有暴露该问题。供应商任务完成和凭据有效不能证明续写使用了已保存上下文。

## Decision

[上下文仓库](../../../../packages/storage/novel-authoring/src/context-repository.ts)保留严格匹配，只有可见结果为空时才使用 PostgreSQL 规范化并安全引用的词项执行任一词匹配。匹配和相关度评分共用实际查询。两条路径保留十四类来源、租户与小说范围、RLS、状态排除、片段大小和候选数量限制。现有 GIN 表达式不变，是否使用由优化器决定。无词项或没有匹配时返回空候选。

方案参考 [pg_search 的 any_word 机制](https://github.com/Casecommons/pg_search#any_word)，使用 PostgreSQL 原生能力，不增加依赖、迁移、模型关键词抽取调用或公开请求字段。已有结果及按排名保存的上下文快照保持原重放行为。

[worker 预检](../../../../deploy/local-test/context-preflight.mjs)解析固定准备任务的当前身份、核验小说归属，再使用完全相同的指令和限制调用生产检索及排序。连接默认采用只读事务，且只使用 worker 凭据；结果仅包含来源标识、排名和哈希。空上下文会在恢复流程切换供应商及预留预算前阻止执行。完整指令也在独立小说中经部署的固定模型执行，随后检查持久化和重启恢复。

[恢复编排器](../../../../deploy/local-test/real-resume.ts)报告脱敏失败阶段及已知准备任务和生成任务定位。任务完成只描述执行状态；快照断言失败仍是验收失败。独立报告保留原始失败，付费预留预算不会减少。

## Alternatives considered

**换成 web-search 查询。** 普通多词输入仍使用 AND，仅替换解析器不能解决完整指令检索问题。

**增加独立的公开搜索关键词。** 分离检索与创作可能改善相关性，但需要新增 HTTP、队列和持久化请求契约。严格优先回退在现有接口内解决已证明的失败。

**使用最近记录或放宽非空断言。** 最近记录不一定匹配故事请求；删除断言会隐藏历史缺失。空结果继续明确可见。

**引入向量搜索或额外模型调用。** 这需要额外基础设施、索引或付费操作。原生任一词匹配能够完成当前有界回归，无需这些成本。

## Consequences

任一词匹配可能因通用格式词召回弱相关内容，也可能读取更多索引项。候选限制约束返回条数，不等于限制全部数据库工作量。需要在代表性数据上检查计划；小规模 fixture 合理使用顺序扫描。`simple` 字典不提供中文分词，本次修复不承诺通用中文或语义搜索能力。

无密钥测试验证检索、隔离、预算、报告及重启行为，不能证明真实续写成功。已耗尽的 2/2 预算及原失败报告继续作为历史证据；另一次真实验收需要独立预算决定。
