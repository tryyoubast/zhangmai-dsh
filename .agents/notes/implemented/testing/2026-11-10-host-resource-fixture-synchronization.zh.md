# Agent Note: 按自有资源状态同步测试夹具

Status: implemented

[English](2026-11-10-host-resource-fixture-synchronization.md) | 中文

## Problem

释放端口探针并不能为 Worker 预留后继端口。在 Windows 上，其他进程可以在 Worker 绑定之前将该端口用于出站连接。轮询持久化文件也可能在写入者替换文件时持有读取句柄，导致 Windows 共享访问失败。进程冒烟测试中的亚秒级 provider 超时包含序列化和连接启动，因此可能测量主机调度而非心跳处理。

## Decision

[inspector 端口用例](../../../../packages/experimental/inspector/tests/port-selection.host.spec.ts)通过注入监听错误，断言端口被占用时的精确递增顺序，以及权限错误必须失败的行为。成功监听通过端口零完成原子分配。另一个真实 Worker 用例检查所有端点公布内核分配的端口，并验证 HTTP 可达性。

[投影缓存用例](../../../../packages/session/session-projection-cache/tests)先观察现有的持久化存储通知，再打开持久化文档进行比较。它们在触发写入前订阅，并匹配目标记录及预期值，避免创建时的检查点被误认为后续重写完成。断言仍检查磁盘上的身份和投影数据，但不再与写入者的原子重命名竞争。

[headless provider 冒烟测试](../../../../apps/cli/tests/profiles/headless/tests/headless.expected.e2e.ts)继承已发布的流空闲超时配置，在响应头发出时发送注释，并让主响应保持打开，直到标题请求到达。它要求预期的两个请求、provider 默认值、注释、最终输出，以及不存在重试事件。provider 的模拟时钟单元测试负责精确心跳期限，并通过模拟响应体传播取消信号，使缺失的活动续期可以被检测。

[托管镜像假设](2026-09-10-hosted-image-test-assumptions.zh.md)和[会话记录测试集](2026-08-24-session-log-snapshot-corpus.zh.md)决策仍然有效：其进程约束、平台、重放及夹具放置规则，与这里的资源获取和完成通知规则相互独立。

## Alternatives considered

**先探测可用后继端口，再释放端口并启动。** 两次操作之间的可用性可能变化；换一个候选端口探测只会移动同一个竞争窗口。

**轮询文档直到内容匹配。** 在 Windows 上，轮询读取者可能阻止其等待的重命名。存储通知提供了现有的完成信号，无需持有竞争的文件句柄。

**增加重试、放宽断言或全局串行执行。** 这些做法会掩盖资源竞争或缺失的观察。精确的请求和数据断言予以保留，独立测试进程仍拥有各自的资源。

**在进程冒烟测试中保留严格的亚秒级超时。** 进程启动和请求准备不受模拟时钟控制。确定性的 provider 测试负责期限行为，进程冒烟测试负责组装后的应用。

## Consequences

测试保留真实网络和持久化文件证据，同时将主机资源分配与确定性的错误及时钟行为分开。生产环境的重试、权限错误、超时和缓存写入策略保持不变。每个夹具负责并等待其监听器、Worker、订阅或存储上下文的清理；完成等待的超时仅用于报告失败，不作为就绪延迟。
