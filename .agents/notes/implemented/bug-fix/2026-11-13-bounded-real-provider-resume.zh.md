# Agent Note: 凭据预检与有界的真实供应商恢复

Status: implemented

[English](2026-11-13-bounded-real-provider-resume.md) | 中文

## 问题

验收在创建业务准备数据或使用剩余生成额度前，需要区分凭据拒绝与创作功能失败。重启后的验收进程无法推断之前的供应商请求是否已计费。重新创建两次任务预算、退还失败提交或允许并发改变 worker 端点，都可能超出操作者批准的额度，并覆盖已有证据。

## 决策

[本机验收参考](../../../../deploy/local-test/README.zh.md#real-provider-acceptance)负责命令与恢复步骤。[供应商检查器](../../../../deploy/local-test/provider-check.mjs)通过隔离的 Compose 工具请求官方模型目录，使用与 worker 相同的网络和供应商密钥，要求在 15 秒内返回 HTTP 200 且包含配置的模型。工具不持有数据库凭据，也不挂载应用 home；只读脚本绑定提供当前代码。固定诊断保留状态与模型是否存在，不含响应正文、密钥或异常原因。管理命令单独报告宿主机密钥文件解析后的路径与修改时间。

[预算管理模块](../../../../deploy/local-test/real-budget.ts)通过排他创建的锁，覆盖预检、固定模型准备、付费任务、重启及固定 worker 恢复。普通验收拒绝任何已有预算；显式恢复要求两次任务恰好已提交一次。已有锁不会被自动删除。预留在 HTTP 提交前原子持久化下一次计数，且不因中断或供应商失败而退还。

模拟验收与服务启动、重启、关闭和重置使用同一把锁。它们不能在付费尝试期间重新创建共享 worker，也不能将模拟请求送到临时启用的真实端点。

恢复流程在业务写入前检查 HTTPS 就绪状态、模拟验收成功证据与供应商凭据。它在新账户和小说中，使用固定模型准备全部十四种草稿目标类型，重启并验证存储数据。[上下文预检决策](2026-11-13-context-retrieval-fallback.zh.md)要求在切换供应商和预留最后一次任务前，由 worker 使用完整续写指令执行只读检索。真实生成仅发起一次，为第 2 章生成人物、地点与章节草稿，供应商调用限制为一次，且不启用 enrichment 或自动重试。第二次重启核验已保存草稿结果及上下文标识、排名与哈希。持有锁的各阶段无论成功或失败，均会恢复 worker，并在解锁前核验。凭据拒绝不改变已提交计数。

恢复报告使用唯一名称，并保留原真实验收报告。证据只含安全定位信息、场景结果及固定准备数据标识。[Staging 架构决策](../architecture/2026-11-11-local-novel-staging.zh.md)继续负责 profile 组合、受限数据库归属、持久化队列与无密钥 CI；本记录负责付费任务恢复规则。

## 考虑过的替代方案

**通过生成请求验证凭据。** 这会在准备数据与持久化上下文检查运行前使用剩余额度。模型目录无需提交生成任务，就能验证凭据与模型可用性。

**重置预算或退还失败调用。** 失败或中断的客户端无法证明供应商没有接收请求或计费。提交前预留可在任务未产出有效结果时，仍然维持批准的最大次数。

**仅在更新预算时加锁。** 另一验收进程可能在准备或核验期间改变 worker 端点。锁覆盖完整验收过程及恢复。

**复用之前的报告与业务准备数据。** 这会混合不同尝试，使原失败更难核查。新的固定模型数据集与唯一报告无需额外付费准备请求，即可保持归属清晰。

## 影响

一次付费尝试可能在预留后损失，却没有完成结果。遗留锁需要操作者调查；自动恢复无法证明持有者已经停止，或供应商未接收请求。模型目录检查成功不能证明生成额度、输出有效性、发布或重启恢复一定成功。模拟测试验证拒绝、命令路由、锁与预算行为；只有本机操作者的实际报告能证明真实供应商验收完成。本变更不引入产品认证、授权、业务逻辑或数据库迁移。

预算预留先同步临时文件，再原子重命名；在 POSIX 上还同步父目录。Node 在 Windows 上不提供目录同步；中断测试覆盖进程退出，不覆盖突然断电或存储控制器故障。恢复过程不会减少已有计数。
