# Agent Note: 可移植 CI 运行器与发布前提

Status: implemented

[English](2026-11-09-portable-ci-prerequisites.md) | 中文

## 问题

拉取请求的必需检查不能假定有权使用组织的大型运行器标签。标准托管机器也需要比企业池更小的进程预算。在这些检查能够验证应用改动之前，创作包的 manifest（元数据清单）必须符合仓库现有的 Cordis 与发布规则。

## 决策

[拉取请求 CI](../../../../.github/workflows/ci.yml) 默认使用 GitHub 托管的 `ubuntu-24.04` 与 `windows-2025`。`DSH_CI_RUNNER_PROFILE=enterprise` 选择现有的 Linux 与 Windows 大型主运行器池。各平台的 `blacksmith` 或符合条件的 `selfhosted` 故障切换优先于该配置。Dependabot 仍被排除在持久化池之外，并回退到所选的托管配置。兼容性与判定作业在故障切换之外保持使用标准托管容量。

标准托管覆盖率使用两个单 worker 插桩分区、一个豁免 worker，以及门禁并发度一。其他重型聚合流程及其显式配置的 lint、发布检查、浏览器和快照 worker 均使用二。企业与故障切换运行器保留现有预算，包括自托管 Linux 的快照上限。[故障切换手册](2026-07-26-ci-failover-runbook.zh.md)、[Blacksmith 决策](2026-09-09-blacksmith-failover-leg.zh.md)与[原生 Windows 决策](2026-08-08-native-windows-pull-request-ci.zh.md)继续负责信任限制、运行器池恢复与平台验证；本文负责默认选择及标准托管预算。

数据库、认证、创作与创作 HTTP 包声明一致的 `workspace:^` Cordis peer 与开发依赖。HTTP 包携带公开发布元数据。[数据库载荷策略](../../../../scripts/check-workspace-constraints.ts)仅在构建产物之外允许迁移根目录中的 SQL 文件、迁移日志与两个具名部署脚本。Drizzle 配置、源码、快照元数据与映射文件仍被排除；无关包的载荷规则保持不变。

沙箱初始化下载经过审核的 Ubuntu Noble bubblewrap 更新包，解压前验证 SHA256；命名空间功能探针仍为必需步骤。各包 README 记录不发布不变量伴生模块的依据，模块图按当前包声明生成。重复列构建器每次分配新实例，已提交的 Drizzle 元数据快照固定所有列顺序、默认值、约束与索引。共享会话字段选择和已保存上下文映射保留现有校验及事务归属。

## 曾考虑的替代方案

**所有位置都要求企业运行器标签。** 没有这些标签的仓库将无法完成必需检查。

**在标准托管运行器上复用企业并发度。** 覆盖率分区与并发工具进程会争抢更小的 CPU 和内存配额。分别设置预算既保留企业配置，也约束标准托管负载。

**发布整个数据库源码或脚本目录。** 受控迁移入口导入构建后的 JavaScript，只需要 SQL 日志和已审核脚本。扩大目录范围会让无关源码或未来部署辅助脚本未经审核就进入发布包。

## 后果

必需覆盖率还验证迁移资源清理、认证失败、创作数据校验与 HTTP 错误路径。校验后的数组结果和路径段保留完整类型，穷尽目标类型的分支继续受到编译器返回路径检查。移除不可达的重复判断，避免构造不可能的解析状态来覆盖测试；不支持的目标、无效凭证、跨租户访问和非法数据仍有可执行的拒绝测试。覆盖率阈值与排除范围保持不变。

标准托管验证以并行吞吐量换取可移植调度。工作流测试求值默认、企业、故障切换与 Dependabot 的路由及资源预算；manifest 测试拒绝扩大数据库载荷，同时保留源码与映射文件拒绝规则。这些检查证明配置行为；平台运行时与全量覆盖率证据仍由 CI 负责。现有故障切换与原生 Windows 笔记仅在默认运行器及资源描述方面被部分取代，其独立的运维依据仍然有效。
