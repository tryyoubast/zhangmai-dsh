# Agent Note: 应用数据文档归属

Status: implemented

[English](2026-11-04-application-data-documentation-ownership.md) | 中文

## 问题

应用数据库、认证和小说创作包缺少完整的公开 JSDoc，虽然导出普通库 API，却使用插件式 README 分类。HTTP 插件注入的控制器也缺少目录归属。这些缺口阻塞文档检查，并让读者难以从所属参考文档确定运行时组合、数据库权限及模型可见的生成输入。

## 决策

公开声明根据实现记录参数、结果、事务与所有权。PostgreSQL、认证和小说创作包采用库 README 格式并登记到经过审查的库清单；HTTP 适配器保留插件格式，记录真实注入依赖。数据库子系统负责连接池生命周期、可信 RLS 身份以及部署／运行时角色分离。HTTP 子系统负责注入的平台控制器及其请求／响应类型。

数据库、认证和 HTTP 适配器 README 采用经过审查的简式模型体验，因为各自直接职责不构造模型请求。创作 README 使用结构化条目记录 DeepSeek 适配器的固定系统指令与动态用户 JSON，包括 token 增长和 Provider 管理的缓存。JSDoc 变化后重新生成源码派生目录，包括源码行号引用与运行时 Cordis 目录。

这些包级登记落实现有的 [README 分类](../../../skills/dsh-doc/SKILL.md)、[模型体验](2026-07-12-package-model-experience-contract.zh.md)和 [Agent Note 格式](2026-07-05-uniform-agent-note-format.zh.md)规则。这些具有独立价值的规则决策保持有效。新数据库参考文档仅保留在仓库中；现有网站路由保留其发布策略。

## 考虑过的替代方案

**跳过失败检查或增加宽泛豁免。** 这会掩盖文档缺失，并允许新增导出或服务在丢失所属文档时不被检测。现有检查及其拒绝案例继续执行。

**把所有包都描述为插件。** 库没有挂载入口。插件安装说明会暗示模块导出无法提供的激活路径。

**把小说生成归类为与模型无关。** DeepSeek 适配器直接发送提示词与序列化上下文。简式分类会隐藏真实模型输入和请求大小增长。

**把应用 PostgreSQL 归入通用 KV 页面。** 两者的数据、角色和事务职责不同。独立数据库参考保留这种区分，同时避免重复 SQL 声明。

## 后果

源码注释和经过审查的分类表负责文档生成器消费的事实。中英文页面一起更新，并显式记录配对。API 签名、业务行为、迁移 SQL 和依赖版本保持不变；生成目录反映已经声明的控制器及其已记录方法。

验证使用导出 JSDoc 检查、README 与目录测试、翻译配对、完整 `doc-sync`、TypeScript、lint 和网站投影／构建检查。静态测试确认文档和生成器一致性；本次文档修复不建立新的生产数据库或 Provider 行为保证。
