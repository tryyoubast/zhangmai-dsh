# Agent Note: 应用数据回调与输入校验

Status: implemented

[English](2026-11-04-application-data-lint-baseline.md) | 中文

## 问题

认证路由的 Promise 会绕过外层错误处理，脱离对象调用的会话解析方法会丢失接收者。过早的类型断言还将不可信 JSON 描述成已校验值。PostgreSQL 驱动会等待异步连接钩子的返回值，但依赖声明却将它描述为同步回调。

## 决策

认证分发在现有错误处理范围内等待每个路由，通过所属对象调用会话方法。解码后的 JWT 对象和 Provider 记录在校验前保持 unknown。HTTP 和物化共享固定草稿目标类型谓词；Provider 数组含有非法元素时直接失败，不丢弃元素。持久化锁调用保留仓库接收者和失败清理；PostgreSQL 结果存储通过所属连接池调用连接获取方法。

连接池使用私有配置类型描述需要等待的连接钩子。初始化失败会拒绝获取连接并关闭该连接；角色校验不会脱离连接获取流程执行。Drizzle 数组回调保留现有表元数据。迁移 SQL、角色授权、令牌生命周期和刷新令牌轮换仍由各自机制负责。

[数据库与发布决策](../architecture/2026-09-23-postgres-novel-drafts-and-review.zh.md)、[幂等写入决策](2026-10-29-atomic-ai-idempotent-draft-writes.zh.md)和[文档归属决策](../process/2026-11-04-application-data-documentation-ownership.zh.md)继续有效；本修复不替代这些机制。

## 考虑过的替代方案

**抑制诊断或将解析数据断言成领域类型。** 这会掩盖非法运行时输入和回调义务，无法保证它们成立。

**丢弃连接钩子的 Promise。** 这会允许连接在权限校验完成前交给调用方，并让初始化失败脱离连接获取流程。

**对整个仓库自动修复。** 回调时序、接收者绑定和数据库元数据需要对照所属实现检查；修复只覆盖受影响的包。

## 影响

定向回归测试覆盖异步 HTTP 失败、依赖实例的回调、非法 JSON、固定草稿目标和连接获取顺序。规范化的 Drizzle 元数据 fixture 检查映射等价性。包测试、lint、TypeScript 和文档检查共同验证修复，不改变生产数据库对象，也不放宽校验规则。
